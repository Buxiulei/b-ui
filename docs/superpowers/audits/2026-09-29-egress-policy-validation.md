# 住宅出口策略验证记录

## 实际转发验证

测试入口：`cargo test -p bui-schema --test kernel_relay_policy -- --nocapture`。测试将生产 Rust renderer 输出交给真实 sing-box；只移动监听端口、提供离线 DNS、替换供应商为回环 SOCKS/HTTP 模拟端，并关闭持久缓存。测试不使用生产配置或外网。

覆盖：A/B 不同端口与自动域名策略隔离；B → A → B 热切后新流使用新策略，已有 B TCP 保留；half-close 后完整响应；私网直连；HTTP/SOCKS 混池；UDP 双向与同会话源端口；IP-only HTTP Host 嗅探和原始 FQDN 不改写。UDP selector 部分在固定 1.14 轨道执行，TCP/HTTP 与策略检查在 1.12/1.13/1.14 全部执行。

IP-only 公网目标用例将 `direct` 最终接收器替换成本机 fake SOCKS，保持生产路由规则和目标元数据，防止失败测试访问外网。该用例验证路由选择，真实 direct 网络栈另由回环用例覆盖。

有两项回归先实际失败、再验证修复：

- 在 wrapper 前解析 UDP 会丢失域名，导致实际出口的自动域名规则失效；解析移至策略匹配之后恢复。
- 日志在产生后回滚至旧拓扑时，单条 UUID 内层错误加外层副本会提前达到哨兵阈值；含 UUID 的批次禁用旧形态归因，避免重复计数。

## 回环成本

环境：macOS arm64、sing-box 1.14.2。每种模式启动一个新内核；25 次预热后 1000 次短连接，10 次 server-first banner，4 次 32 MiB 下载，另持有 50 条 TCP 采样 FD。baseline 从同一 renderer 的无策略输出中移除回环 wrapper 和策略入站规则，selector 直接指向模拟供应商，保留入口嗅探。

| 模式 | 短连 p50 / p95 / p99（ms） | FQDN 服务器先发数据 p50（ms） | IP-only 服务器先发数据 p50（ms） | 空闲 / 50 流 FD |
|---|---:|---:|---:|---:|
| baseline | 0.431 / 0.624 / 0.891 | 302.17 | 302.69 | 10 / 110 |
| wrapper，无自动域名规则 | 0.541 / 0.811 / 1.196 | 303.23 | 303.28 | 12 / 212 |
| wrapper，有自动域名规则 | 0.537 / 0.778 / 1.222 | 303.22 | 604.44 | 12 / 212 |

常规短连接中位开销约 0.11 ms，每条活跃 TCP 多 2 个 FD，本用例的两个策略监听另多 2 个 FD。1000 次短连内核 CPU 时间增量为 0.27 s → 0.44–0.45 s，约为原来的 1.6–1.7 倍。三个模式长流吞吐中位数约 1.5 GiB/s，但样本少且预热噪声明显，不据此宣称生产吞吐改善。

首版对已知 FQDN 也再次 sniff，使 server-first 约多等 300 ms；修正后已知域名不重复等待。仍有真实代价：**IP-only + 出口有自动域名规则 + 客户端等待服务器首包时，第二次 sniff 增加约 300 ms**。此处为了重建 Host/SNI 元数据保留等待，不能用 HTTP 快速测试掩盖。

这些数字来自单机、顺序测试、模拟对端，不是公网 SLA。没有测试生产满载、丢包 QUIC 吞吐或无限长流排空；不证明端到端卡顿完全消失。

## 故障归因和发布边界

真实内核实验证实：供应商 REP2/REP4 会分别产生内层稳定 UUID 的真实错误，以及外层 selector 的合成 REP1。内层使用 UUID 定位，外层不作为独立供应商故障。未知 UUID、API 不可读及回滚混批有业务回归保护。

本阶段不引入自研转发协议。Rust 控制面生成路由、管理选择和解释故障，实际协议仍由上游内核处理。热切保留连接，但修改策略或池结构仍会重启整个 relay；同 UUID 跨配置代际的旧日志仍需未来 generation/epoch 处理。要消除配置更新导致的断联，需要后续单独实现准备、验证、发布新流和旧流排空，不能将本阶段描述为已经完成该能力。
