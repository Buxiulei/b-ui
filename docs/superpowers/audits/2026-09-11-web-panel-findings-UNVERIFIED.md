## 子系统

web/server.js (Node admin panel, 2721 lines) + web/app.js (1222) + web/index.html (505)

## 概述

b-ui-admin is a single-threaded Node process bound to 127.0.0.1:8080 (core.sh:1729) and exposed to the world through Caddy `${DOMAIN} { reverse_proxy 127.0.0.1:8080 }` (core.sh:865-868). It is the control plane: it owns users.json and rewrites the auth blocks of config.yaml / config-residential.yaml and the clients list of xray-config.json on every user change (server.js:276-390), restarting hysteria-server, hysteria-residential and xray (userpass auth has no hot reload). It is NOT on the data path: since v3.5.15 (commit 5b6cde3) core.sh:659-664 converts hysteria auth from `http -> /auth/hysteria` to local `userpass` at install time and update.sh:1090-1120 (block D6) does it on every update, so the /auth/hysteria endpoint and checkUserLimits() are unreachable on any host with jq — and with them the ONLY enforcement of expiresAt/trafficLimit/monthlyLimit/speedLimit disappeared (grep of those keys in server/ and b-ui-client.sh hits only the seed user in core.sh:523). Traffic accounting polls hysteria trafficStats 127.0.0.1:9999 every 10s (server.js:1034-1050, 1423-1460) and the xray stats API via `xray api stats` CLI spawns (1071-1110); the residential hysteria instance's trafficStats :9998 (core.sh:532) is declared (server.js:51) but never polled, so HY2住宅 traffic, online state and /kick never reach that instance. Subscriptions: three unauthenticated generators (/api/sub 1808-1929, /api/subscription 1783-1804 -> generateSingboxConfig 650-848, /api/clash 1932-1951 -> generateClashConfig 850-1032) plus app.js genUri (293-350) each re-derive the same 4-node set (Reality直连 :10001 / Reality住宅 :10002 / HY2直连 :PORT / HY2住宅 :40000) with four copies of the proto×residential decision. Client distribution: /install-client?key= (1513-1631) and /packages/* (1636-1691) serve b-ui-client.sh with SCRIPT_VERSION stamped from version.json (31-35); the key gate is nullified by unauthenticated GET /api/install-command (1770-1780) which returns the key, and /packages/b-ui-client.sh needs no key anyway. A second GitHub kernel poller (syncKernels 1242-1419) lives inside the panel next to update.sh's `kernel` cron. Residential endpoints (2156-2515) shell out to residential-helper.sh via spawnSync and read singbox-relay.json/.resi-health-state.json/Clash API :9091.

## 千人规模的隐患

- Every user add/delete/password change rewrites the userpass block and restarts hysteria-server AND hysteria-residential AND xray (web/server.js:276-290, 316-326, 303-314, 328-390) — at 1000 users each onboarding drops every active session; xray HandlerService (enabled core.sh:779) is never used for hot add/remove.
- users.json is a single pretty-printed JSON array re-read on every subscription request and every /api/* user op (web/server.js:270-274) and rewritten in full every 10s while any traffic flows (1453) with fs.writeFileSync (non-atomic; a crash mid-write makes loadUsers return [] and the next saveUsers would push an empty auth block to all three services).
- Traffic/online polling does 2 synchronous `xray api stats` spawns per VLESS user (web/server.js:1083-1096, 3s timeout each) every 10s AND again on every /api/stats and /api/online, which the SPA polls every 5s (web/app.js:110-114) — blocks the single event loop that also serves subscriptions and /install-client.
- /api/subscription and /api/clash spawn `residential-helper.sh domains` synchronously per request when domains follow the default (web/server.js:492-506, 520) — 1000 clients refreshing subscriptions = 1000 bash spawns.
- No rate limiting or caching on unauthenticated generators; each /api/sub call parses config.yaml, xray-config.json, reality-keys.json, port-hopping.json (getConfig 392-490) and each /api/kernel-versions call runs 3 shell pipelines (1724-1734).
- hysteria-residential traffic (:9998) is never accounted (web/server.js:51 unused), so quota data is wrong for every residential user regardless of scale; and residential sessions cannot be kicked (2070 -> port 9999 only).
- lastTraffic/lastXrayTraffic live only in process memory (1422, 1069): each b-ui-admin restart (every update, every password change) double-counts cumulative hysteria counters (1437-1438).
- The whole users list with passwords/uuids is shipped to the browser every 5s (web/server.js:1957, web/app.js:114) and the table is re-rendered from scratch (143-176); at 1000 users that is hundreds of KB per poll per tab.
- syncKernels runs inside the panel process capped at MemoryMax=200M/MemoryHigh=150M (core.sh:1754-1755); a slow GitHub download shares the event loop with subscription serving.
