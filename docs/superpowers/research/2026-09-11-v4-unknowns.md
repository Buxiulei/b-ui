## 1. Hysteria2 `auth.type: command`

### 1.1 结论（可直接指导实现）

| # | 结论 | 置信度 |
|---|---|---|
| H1 | 调用形态固定为三个位置参数：`<command> <addr> <auth> <tx>`。`addr` = 客户端 `host:port`（`net.Addr.String()`）；`auth` = 客户端发来的认证载荷**原文**（v2rayN 用 `hysteria2://user:pass@host` 时即 `user:pass` 一整串，内核不拆分）；`tx` = 服务端裁剪后认定的该连接下行速率，字节/秒，十进制整数。 | documented [1][2] |
| H2 | 不注入任何环境变量（继承 `hysteria-server` 进程环境）；stdin 为空（Go `exec.Cmd.Stdin=nil` → `/dev/null`，读到 EOF）。 | inferred [1]（源码未设 `Env`/`Stdin`，按 Go `os/exec` 语义） |
| H3 | 允许 = 退出码 0，stdout 内容 `TrimSpace` 后作为 `id`；拒绝 = 任何非 0 退出码**或**命令根本无法执行（路径不存在/无执行权限），两者内核侧不可区分，都只表现为鉴权失败。 | documented [1][2] |
| H4 | `id` 与 password/userpass/http 鉴权器返回的 id 走同一路径：存为 `h.authID`，原样用于 `LogOnlineState`、`LogTraffic`、事件日志、`/dump/streams` 的 `AuthID`，即 **`/traffic` 与 `/online` 的键就是钩子打印的字符串**。 | documented [3] |
| H5 | stdout 之外的输出不会进内核日志：`cmd.Output()` 只在出错时把 stderr 收进 `ExitError.Stderr`，而内核对 err 一律 `return false, ""`，不打印。钩子若要留诊断，必须自己写日志（文件或 journald），不能依赖 stderr。 | inferred（[1] 源码 + Go `Cmd.Output()` 语义） |
| H6 | 时机：**每条 QUIC 连接最多调用一次**——该连接上第一个命中鉴权路径的 HTTP/3 请求触发；`h3sHandler` 用 `authMutex + authenticated` 去重，同一连接后续鉴权请求直接回缓存。客户端重连产生新 `quic.Conn` → 新 `h3sHandler` → 必然再调一次；端口跳跃不产生新连接（QUIC 连接迁移），不重复调用。 | documented [3] |
| H7 | 不阻塞 accept：`Serve()` 的 Accept 循环对每个新连接 `go s.handleClient(conn)`，鉴权在该连接自己的 goroutine 内执行；一次挂起的钩子只卡住它所属连接（连同该连接的 `authMutex`），不影响其他连接的 accept 或鉴权。 | documented [3] |
| H8 | **内核不设超时**：`command.go` 用裸 `exec.Command(...).Output()`，无 `context`/`Cmd.Cancel`/`WaitDelay`；对比 `HTTPAuthenticator` 有 `httpAuthTimeout = 10s`。钩子挂起 → 该连接永久等待。 | documented [1][4] |
| H9 | 无并发限流/进程池：每次鉴权 fork+exec 一个全新进程，内核侧没有任何节流；`userpass` 是纯内存 map 查找。两路调研均未在 issue 库中找到 command 鉴权高并发性能问题的报告（只命中 #1071 误配置、#1350 热重载诉求）。 | inferred（源码对比）；issue 层 unknown [5][6] |
| H10 | `GET /traffic?clear=1`：`clear` 用 `strconv.ParseBool` 解析（`1/true/T` 均可）；为真时在同一把 `Mutex.Lock()` 临界区内完成「序列化当前 `StatsMap`」与「替换为新空 map」，而 `LogTraffic` 也要拿同一把写锁，因此**读取与清零对并发计数是原子的，不丢不重**。返回体 `{"<id>":{"tx":<u64>,"rx":<u64>},...}`。 | measured（源码加锁逐行核对）[7] |
| H11 | `GET /online` 返回 `{"<id>":<int>}`，值 = 该 id 当前**在线 QUIC 连接数**（设备/实例数），不是代理流数；鉴权成功 +1，`handleClient` 结束 −1，≤0 删键。 | documented [7][3] |
| H12 | `POST /kick` 请求体是 JSON 字符串数组 `["alice","bob"]`（解析失败 400）。语义是**一次性标记**：只把 id 塞进 `KickMap`，不主动断连；该 id 的连接**下一次 `LogTraffic`（即下一次有 TCP/UDP 字节被转发）**时返回 false → 拷贝循环退出 → 以 `closeErrCodeTrafficLimitReached(0x107)` 关闭 QUIC 连接，并从 `KickMap` 删除该标记。完全空闲的连接被 kick 后不会立刻断；客户端有重连逻辑，重连会再次走钩子。 | documented [7][3]；「空闲连接不断」为源码推断 |
| H13 | trafficStats API 若配置 `secret`，要求 `Authorization` 请求头**精确等于** secret 字符串（无 `Bearer ` 前缀），否则 401。 | documented [7] |
| H14 | 不支持 SIGHUP/配置热加载：`app/cmd/server.go` 仅 `signal.Notify(os.Interrupt, SIGTERM)` → 优雅关闭；全仓库无 SIGHUP/fsnotify/WatchConfig。维护者对 #1350 的答复是「改用 http 或 command 鉴权」。`userpass` 用户表变更必须重启。 | documented [8][6] |

两路调研在 H1–H14 上无实质分歧（一路把 H2 标 documented、一路标 inferred，取 inferred；一路把 H10 标 documented、一路标 measured，取 measured）。

### 1.2 对 spec 的影响

1. **§3.2 原句**「内核每次建连以参数调用钩子（参数形态由 Sonnet 调研确认，见 §10）」→ 改为：「内核对每条新 QUIC 连接调用一次 `bui auth-hook <addr> <auth> <tx>`（无环境变量、stdin 为空）；`auth` 是客户端 `hysteria2://user:pass@` 里的 `user:pass` 原串，钩子按第一个 `:` 拆分用户名与密码；放行则 stdout 打印 `user_id` 并退出 0，该字符串即 `/traffic`、`/online`、`/kick` 的键。」
2. **§3.2 需新增**：「内核对钩子**不设超时**，钩子必须自设硬超时（建议 ≤ 2 秒，读快照失败或超时一律拒绝，fail-closed），且钩子只能靠自身写日志，stderr 不会出现在 `hysteria-server` 的 journal 里。」
3. **§3.2「代价」句**保留，但补一句：「内核对并发 fork 无任何限流，`auth-hook` 子命令必须走极简路径（不初始化 tokio/tracing/配置加载，只读一个小文件），M5 压测同时看 PID/fd 峰值。」`userpass` 退路的「内容比对重启」前提被 H14 证实（无热加载）。
4. **§4.2 原句**「hysteria 直连 `GET /traffic?clear=1`（9999）+ 住宅（9998）增量相加」→ 语义成立（H10 原子），补注「请求头 `Authorization: <secret>` 无 `Bearer` 前缀」。
5. **§4.2 原句**「在线：hysteria 两个 `/online` 的并集」→ 明确「`/online` 的值是 QUIC 连接数，面板『在线』按 `>0` 判定即可」。
6. **§4.2 原句**「到期 / 超限 / 禁用 → 快照标记拒绝 + 对两个 hysteria `POST /kick`」→ 补注「`/kick` 只是标记，要等该用户下次有流量才断连，空闲连接可能长期不断；被踢后客户端会重连并再次过钩子，因此**快照拒绝是主保障，kick 只是加速**。请求体 `["<user_id>", ...]`。」

### 1.4 未决问题

- command 与 userpass 在建连风暴下的量化差异（fork 开销、PID/fd 峰值）没有官方数据，只能靠 M5 压测（`sleep`/`echo` 脚本 vs userpass 同并发对比）。
- 是否有比 v2.12.2 更新的版本给 `CommandAuthenticator` 加了超时/`CommandContext`，未核对；实现按「无超时」设计即可向下兼容。
- `/kick` 对完全空闲连接的边界行为（是否会因 keepalive 触发 `LogTraffic`）无 issue 佐证；源码看 keepalive 不走 `LogTraffic`。

### 2.2 对 spec 的影响

1. **§5.4 原句**「② `ports_allowed` 非空时 `port_range` 取反 → direct」→ 写法确认：`{"port_range":["1:79","81:442","444:65535"],"outbound":"direct"}`（P0 计划测试断言已如此写，无需改）；补注「`port_range` 必含冒号，单端口用 `port` 数组」。
2. **§5.3 原句**「切换通过 Clash API `PUT /proxies/resi-pool`」与 **§5.4**「relay 重启是唯一掐连接的动作」——两者只在 `resi-pool` 选择器保持 `interrupt_exist_connections: false`（v3 现状）时同时成立。spec 应显式写死这一取值，避免实现时误设 true 导致每次健康切换掐断所有住宅连接。
3. **§5.5 原句**「relay 用 `auth_user` 分组」→ 字段名与三版可用性确认；补注「`mixed` inbound 需配 `users[]`，规则用 `auth_user`（不是 `user`）」。
4. **§6 原句**「`tun` inbound，`interface_name: bui-tun`，`stack: mixed`，`auto_route` … `sniff` + `hijack-dns`」→ 字段全部确认；补一句「DNS server 用 typed 写法且**凡需经代理解析的 server 必须显式 `detour`**（typed server 默认是空 direct dialer，不是 default outbound）；1.14 弃用清单不涉及本配置，但生成器**禁止**出现 `rule_set`/`download_detour`/legacy DNS 字符串/`inet4_address`」。
5. **§8 测试策略**（隐含）：`sing-box check` 是严格校验器，生成器测试可直接以「1.13.19 与 1.14.x 二进制 `check` 退出 0」为门槛，任何拼写错误都会被抓到；不必自己写 schema 校验。

### 3.2 对 spec 的影响

1. **§3.3 原句**「proto 从 Xray-core 仓库按 pinned 版本 vendor 进仓」→ 具体化为 X8 的 10 个文件清单（pinned `v26.3.27`），`build.rs` 以 vendor 目录根为 include path；AddUser 请求组装写明两层 `TypedMessage`：`operation.type="xray.app.proxyman.command.AddUserOperation"`，`User.account.type="xray.proxy.vless.Account"`，`Account{id, flow:"xtls-rprx-vision"}`，`User{level:0, email:<user_id>}`。
2. **§3.3 原句**「`StatsService.QueryStats(pattern="user>>>", reset=true)` 一次拉全量增量」→ 成立（子串匹配，`user>>>` 命中所有用户计数器；单计数器原子清零不丢数）；补注「返回的是各计数器各自原子清零的值，不是同一时刻快照，累加语义正确」。
3. **§3.3 需新增**：「用户的 `email` 即 gRPC 侧唯一键（`RemoveUser` 只认 email、stats 名也用 email），state 里 `user_id` 与 xray `clients[].email` 必须一一对应且不可为空。」
4. **§4.2 原句**「到期 / 超限 / 禁用 → … + Xray `RemoveUser`」→ 补注「`RemoveUser` 只阻止新握手，**已建立的 REALITY 连接会一直活到客户端自己断开**（Xray #5844 未合并）；v4 不做进程重启硬切，接受该窗口；面板说明写明『超限用户的既有连接可能延续到其断开』」。若产品上不可接受，唯一可选项是把 `clients` 移除后重启 xray（会掐所有用户），需另行决策。
5. **§3.3 原句**「`xray-config.json` 里的 `clients` 列表同步维护，只为重启后持久化」→ 成立，且 REALITY 侧无额外动作（X11）。
6. **§7 / 退路**：`xray api adu` 需要完整 inbound JSON 文件，CLI 退路要先渲染一份临时 inbound 片段再调用；`rmu` 可直接传 `-tag` + email。
