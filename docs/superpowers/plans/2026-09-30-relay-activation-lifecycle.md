# 出口选择与激活生命周期实施计划

设计：[出口选择与数据面激活分离](../specs/2026-09-30-relay-activation-lifecycle-design.md)。基于 PR #2 的固定 1.14.2 数据面与 UUID 出口策略。

1. 用真实 render → plan → apply 复现保存默认选择导致 relay 重启。
2. 为 relay 定义只排除全局 selector.default 的结构指纹，接入受管文件重启策略；其他网络字段一律保留。
3. 先以失败测试暴露对账器的写盘/激活混淆、同字节未激活、同服务部分写入失败和外部漂移。
4. 将文件确认拆为结构激活键和完整内容指纹；需激活的候选记录由服务成功加载后提交，回滚和自重启请求不确认。
5. 验证默认选择保存后再对账零动作、旧记录迁入一次保守激活后收敛、回滚成功也不确认候选；回归 Xray 用户热更新。
6. Linux workspace、真实 1.14.2 TCP/UDP、clippy、fmt、独立审查与 GitNexus 影响核对后提交后续 PR。部署说明明确首次建立证据可能重启 relay 与 Xray。

配置代际的准备/发布/排空是下一完整阶段，设计中已记录依赖事务与资源约束，本阶段不部署或声称实现该能力。
