# b-ui v4 实施总纲（子项目拆分、接口契约、并行编排）

> **For agentic workers:** 本文不是可直接执行的任务计划，而是 5 份子项目计划的索引与契约。执行请进入各子项目计划（`2026-09-11-v4-p0-foundation.md` 等），每份都要求 `superpowers:subagent-driven-development`。

**Goal:** 按 `docs/superpowers/specs/2026-09-11-v4-architecture-design.md` 交付 v4.0.0：单二进制 `bui` 控制器 + `bui-schema` 共享渲染 crate + Rust 客户端 `bui-c`，在 bwg-rick 通过 M1–M5 验收。

**Spec:** `docs/superpowers/specs/2026-09-11-v4-architecture-design.md`

## 全局约束（每个子项目隐含）

- Rust stable ≥ 1.85（本机 1.93），edition 2021，`cargo clippy -- -D warnings` 零告警，`cargo fmt --check` 通过。
- 发布目标 `x86_64-unknown-linux-musl`（本机已装）与 `aarch64-unknown-linux-musl`（CI）；依赖优先纯 Rust；TLS 用 `rustls` + `ring`，禁止 openssl。
- 协议集、端口、标签、UUID、密码与 v3 一致；订阅输出必须与 v3 golden 样本逐项相等（spec §4.4、§8）。
- sing-box 配置兼容 1.12–1.14：typed DNS servers、TUN `address` 数组、rule action（`sniff`/`hijack-dns`/`reject`）、`route.default_domain_resolver`、**不用** `rule_set` / `download_detour`。
- 凭据、密钥、密码不进 argv、不进日志（`tracing` 字段一律脱敏）；state 与快照文件 0600。
- 生产主机只用别名 bwg-rick / bwg-tizi / baiyi；公开仓库里不出现真实 IP、端口、域名。
- 分支 `v4`；每个任务一个 commit，格式 `feat(scope): …` / `test(scope): …` / `fix(scope): …`，尾部附署名；不 `git commit -a`；不裸 `git stash`；不推送（推送由主理人决定）。
- v3 的 `server/`、`web/server.js`、`b-ui-client.sh` 在开发期**保留**作为移植参照与 fixture 生成器，P5 最后一个任务才删除。
- 每个任务先写失败测试再实现；集成测试用本机真实内核（`sing-box` 1.13.19 `/usr/bin/sing-box`、`xray` 26.3.27 `/usr/local/bin/xray`、`hysteria` 2.12.2 `/usr/local/bin/hysteria`），二进制不存在时 `skip` 而不是失败。

### C2 `bui` 内部模块边界（P1 交付框架，P2/P3 各自填模块）

pub struct Store(Arc<Inner>);   // Clone；写 = 临时文件 + 0600 + rename，写盘前备份，保留 BACKUP_KEEP = 10 份

pub trait Host: Send + Sync {

    fn remove_file(&self, path: &Path) -> Result<()>;
    fn list_dir(&self, path: &Path) -> Result<Vec<PathBuf>>;   // 只返回直接子项，升序；目录不存在 → Ok(vec![])

    fn remove_dir_all(&self, path: &Path) -> Result<()>;
    fn is_symlink(&self, path: &Path) -> Result<bool>;
    fn read_link(&self, path: &Path) -> Result<Option<PathBuf>>;
    fn symlink(&self, target: &Path, link: &Path) -> Result<()>;
    fn set_immutable(&self, path: &Path, on: bool) -> Result<()>;
    fn is_immutable(&self, path: &Path) -> Result<bool>;
    fn run(&self, program: &str, args: &[&str]) -> Result<CmdOut>;
    fn which(&self, program: &str) -> bool;
    fn systemd_daemon_reload(&self) -> Result<()>;
    fn systemd(&self, verb: &str, unit: &str) -> Result<CmdOut>;
    fn unit_is_active(&self, unit: &str) -> Result<bool>;
    fn unit_is_enabled(&self, unit: &str) -> Result<bool>;
    fn unit_exists(&self, unit: &str) -> Result<bool>;
    fn unit_property(&self, unit: &str, prop: &str) -> Result<Option<String>>;
    fn sysctl_get(&self, key: &str) -> Result<Option<String>>;
    fn sysctl_set(&self, key: &str, value: &str) -> Result<()>;
    fn modprobe(&self, module: &str) -> Result<()>;
    fn mem_mb(&self) -> Result<u64>;
    fn arch(&self) -> Result<String>;
    fn hostname(&self) -> Result<String>;
    fn listening_ports(&self, proto: Proto) -> Result<BTreeSet<u16>>;
    fn now(&self) -> time::OffsetDateTime;
    fn journal_read(&self, units: &[String], from: &JournalFrom) -> Result<Vec<JournalRecord>>;   // 日志哨兵（spec §5.7）：`journalctl -o json` 增量读；JournalFrom::{Cursor(String), Since(OffsetDateTime)}
}
pub struct CmdOut { pub status: i32, pub stdout: String, pub stderr: String }   // ok() / success() / failure()
pub enum Proto { Tcp, Udp }

### C3 文件与路径（P1 定义，全体遵守）

**2026-09-12 按 P1 实现回写**（路径全部从 `Paths::base_dir` 派生，`crates/bui/src/paths.rs` 是唯一一份）。服务端 `<base>` = `/opt/b-ui`：

- 期望态与运行时：`state.json`（0600）、`runtime.json`（0600）、`state.backups/`（`state-<stamp>-<nnn>.json`，保留 10 份，`bui upgrade --rollback` 取最近一份）、`auth-snapshot.json`（0600）
- 内核配置：`config.yaml`、`config-residential.yaml`（槽 0）与 `config-residential-<i>.yaml`（槽 1..，每槽一份，空槽产 `Absent`）、`xray-config.json`、`singbox-relay.json`、`Caddyfile`（`caddy.service` 以 `--config /opt/b-ui/Caddyfile --adapter caddyfile` 启动，不再写 `/etc/caddy/Caddyfile`）
- 目录：`bin/`（四个内核 + `bui`；升级时旧版另存 `bin/bui.prev`，`--rollback` 据它还原）、`certs/`、`caddy/`（Caddy 的 `XDG_DATA_HOME` 与 `XDG_CONFIG_HOME`，ACME 账号与证书落在 `caddy/caddy/`）、`packages/`（客户端内核缓存）、`.verify/`（渲染结果过内核校验时的落地目录）、`v3-backup/`（0700，`uninstall_v3` 归档含秘密的 v3 状态文件）
- 其它顶层文件：`manifest.json`（install / upgrade / 每日自检写下的缓存，对账据它决定内核版本）、`relay-cache.db`（relay 的缓存，`RelayOpts.cache_path`）、`auth-hook.log`（`bui auth-hook` 的落盘日志）
- `drift::BASE_WHITELIST` 的 13 项 = `bin` `certs` `caddy` `packages` `state.backups` `.verify` `v3-backup` `state.json` `runtime.json` `manifest.json` `relay-cache.db` `auth-snapshot.json` `auth-hook.log`（`<base>` 顶层允许存在、但不是 artifact 的条目；漂移只看顶层直接子项，不递归 `bin/ certs/ caddy/ packages/`）

进程外接口：unix socket `/run/b-ui.sock`（0600 root，CLI ↔ 守护进程，SO_PEERCRED 鉴权，`paths::SOCKET_PATH`）；CLI 入口符号链接 `/usr/local/bin/bui` 与 `/usr/local/bin/b-ui` 双双指向 `<base>/bin/bui`（`paths::CLI_LINKS`，units 模块作为 `Artifact::Symlink` 自愈，`sudo b-ui` 无参即菜单）。

单元（`MANAGED_UNITS`，6 个完整单元文件，不生成任何 timer）：`b-ui / hysteria-server / hysteria-residential / xray / b-ui-relay / caddy`；外加住宅槽 1.. 的 `hysteria-residential-<i>.service`（spec §5.6，每槽一个；枚举一律经 `reconcile::managed_units(&state)`，词法判定用 `reconcile::is_managed_unit`）。客户端 `/opt/bui-c/{bin/sing-box, profiles.json, config.json}`，`bui-c.service`、`bui-c.timer`。

**manifest 来源与覆盖**：默认 URL 为 GitHub Releases `latest` 的 `manifest.json`（镜像回退与 install.sh 同策略）；`bui upgrade --manifest-url <url|file>` 与环境变量 `BUI_MANIFEST_URL` 可覆盖（P1 实现），用于 M5 的升级/回滚演练——演练用本机 `python3 -m http.server` 托管 CI 产物的 `dist/`，**不依赖公开 Release**，v4.0.0 正式 tag 由主理人在 M5 验收后打。

规则：键名固定 `<name>-linux-<amd64|arm64>`；每个 `url` 指向**裸二进制**（P5 的 Actions 负责把上游 tar.gz/zip 解包后作为 Release 资产重新上传，并算 sha256）；`kernels` 只记版本号，安装时以 `artifacts` 为准；消费方（P1 `kernels::Manifest`、P4 `update::Manifest`）必须按此形状反序列化，未知字段忽略。P1/P4 计划草稿里各自的 manifest 形状以本节为准修订。

### C5 `bui` CLI 与快照契约（P1 定义、P2 写快照、P5 脚本消费）

- `bui --version` 只打印版本号（如 `4.0.0`）；`bui status --json` 输出 `/api/health` 的 JSON；`bui serve`；`bui install [--import-v3] [--non-interactive --answers <file>]`；`bui upgrade [--version <x.y.z>] [--manifest-url <url|file>] [--rollback]`；`bui reconcile [--force]`；`bui set hy2-auth http|command`；`bui auth-hook <addr> <auth> <tx>`；`bui harden-ssh`；`bui menu`（`/usr/local/bin/b-ui` 符号链接无参即菜单）。
- `auth-snapshot.json`（0600，P2 的采样/限额任务原子重写，P1 `install` 首次写入）：`{ "schema": 1, "users": { "<username>": { "user_id": "<uuid>", "hy2_password": "…", "expires_at": null|"RFC3339", "blocked": false } } }`。压测/运维脚本读凭据一律读 `state.json`（`users[].username` / `credentials.hy2_password`），不解析快照。
- 推送与 CI：仓库「不推送」是默认；CI 首跑需要主理人明确授权推送分支 `v4`（P5 计划里写成「报备后执行」），正式 tag 由主理人打。

## 并行编排（Workflow）

1. **P0 工作流**：Task 1–2 串行（scaffold + 模型契约）→ Task 3/4/5/11/12 并行 → Task 6–10 并行（渲染器，依赖 5 的 fixtures 与 12 的关键字表）→ 集成 agent 跑全量 `cargo test`/clippy/fmt 并合并。每个任务：Opus 实现（独立 worktree，分支 `v4-p0-tN`）→ Fable 派生的审查 agent 两段审查（spec 符合性、代码质量）→ 合并到 `v4`。
2. **P0 完成后**：三个规划 agent（Opus，effort high）并行起草 P1、P4 与 P2/P3 的接口任务，Fable 审后各自开工作流；P2/P3 在 P1 前两个任务合并后启动。
3. 每个子项目结束：Fable 在 bwg-rick 做该里程碑验收（spec §9），主理人确认后进入下一个。
4. 监控：Haiku 一次性核对合并结果与测试报告；长跑（soak/压测）用 `nohup` + 标记文件 + `Monitor`。
