# b-ui 4.1 住宅 HY2 改 sing-box 单入站实施计划

> **Fable 额度已耗尽，审查回退 Opus。** 本计划的设计评审、对抗验证与验收裁决由 Opus 承担（模型分工里 Fable 那一档整体降级到 Opus），实施照旧派 Opus 子代理、调研派 Sonnet、一次性巡检派 Haiku。

> **For agentic workers:** REQUIRED SUB-SKILL：用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务逐个实施。步骤用 `- [ ]` 复选框跟踪。每个任务先写失败测试、跑到红、再最小实现、再跑绿、最后一个 commit。

**Goal:** 按 spec `docs/superpowers/specs/2026-09-15-hy2-singbox-residential-design.md` 把住宅 HY2 从「每住宅 IP 一个 apernet hysteria 进程、跳跃段按槽位空间等分」改成「**一个 sing-box hysteria2 入站 `:40000` + 静态凭据池 + 每凭据一个 selector 门 + `auth_user` 路由到各槽出站**」，整段 `41000-50000` 由 b-ui 自管的 nft 表 REDIRECT 到 `:40000`；于是 ① 共享一段跳跃不再跨进程静默丢包，② 增删住宅 IP 与用户全生命周期（建 / 到期 / 封禁 / 解封 / 换槽 / rotate / kick）只经 Clash API 切门、**零重载零刷新订阅**，③ 计量改走自建 sing-box 的 v2ray_api gRPC，④ 受管单元数固定回 6，⑤ 「必须重新获取订阅」整套机制退役。直连 HY2（`hysteria-server`，`:10000` + `20000-30000`）仍用 apernet，**一个字不动**。

**Architecture:** 住宅数据路径变成 `客户端 → UDP :40000 | 41000-50000 | 40001-40007 → [nft inet bui 的 prerouting/output 两条 redirect] → sing-box hysteria2 入站 hy2-resi :40000 → users[] 静态凭据池（password = "{name}:{secret}"）→ route 规则 {"auth_user":["<name>"],"outbound":"gate-<id>"} → selector gate-<id>（成员 deny + slot-0-out..slot-7-out，default "deny"，interrupt_exist_connections: true）→ socks 127.0.0.1:(2080+i) → b-ui-relay 的 slot-<i> 入站 → 住宅上游`。渲染集中在 `bui-schema`：新模块 `hy2pool`（凭据池纯函数）、`render::hy2_singbox`（`hy2-residential.json`）、`render::nft`（`inet bui` 规则集）；`slots` 收缩成「只驱动 relay 入站、xray 槽路由与门位」的分配器（`SlotRes { index, relay_port }`）。`bui` 侧：`Artifact::NftTable` 是 C2 的第 10 个变体、三处幂等重放（单元 `ExecStartPre=-{bin}/bui nft apply`、每轮对账、watchdog 每 60 秒）；新 trait `Hy2ResiApi`（v2ray_api `StatsService` gRPC + Clash API `/proxies` `/connections`）与 `panel/gates.rs` 的纯函数 `expected()` 一起，让门位收敛挂在 `panel::users::sync_users` 里，与它旁边那段 xray 收敛同构；单元名沿用 `hysteria-residential`，`hysteria-residential-1..7` 进 `LEGACY_UNITS`。发布链：只有随发布分发的那一个 sing-box 自建（为了 `with_v2ray_api`），轨道 → `kernels.lock` 的 `build:` URI → CI `go build` → sha 可重现校验，**构建失败则锁不动、发布保持上一版并告警**。

**Tech Stack:** Rust stable ≥ 1.85（本机 1.93，edition 2021）、serde / serde_json / serde_yaml、uuid 1、sha2 + hex、time 0.3、tokio 1、axum 0.8、clap 4（derive）、tracing、anyhow / thiserror、tonic 0.14 + tonic-prost 0.14 + prost 0.14（gRPC 客户端，build 侧 `tonic-prost-build` + `protoc-bin-vendored`）、reqwest 0.12（rustls，blocking + socks）；dev：pretty_assertions、tempfile、tokio `test-util`。前端只用原生 DOM API（`web/app.js` 无构建步骤）。发布链：bash + GitHub Actions + `actions/setup-go`（本计划新增）+ Go 原生交叉编译（`CGO_ENABLED=0`）。集成测试用本机真实内核：`sing-box`（1.12 / 1.13 / 1.14，缺哪版跳哪版）、`xray run -test`、`caddy validate`；`hy2-residential.json` 的 `check` 只在**自建** 1.14 上跑。

**Spec:** `docs/superpowers/specs/2026-09-15-hy2-singbox-residential-design.md`（下称 **spec**，唯一需求来源；§1 背景与目标、§2 架构与 nft、§3 凭据池与门控、§4 状态与迁移、§5 计量与发布链、§6 鉴权语义与文案、§7 订阅与客户端、§8 哨兵/watchdog/自检、§9 回滚、§10 五阶段与判据、§11 风险、§12 待验证、§13 契约影响、§14 终审裁决八条）。上位文档：`docs/superpowers/specs/2026-09-11-v4-architecture-design.md`（§3.1 / §3.2 / §3.4 / §4.2 / §5.6 / §5.7 / §9 被本计划修订）、`docs/superpowers/plans/2026-09-11-v4-master.md`（C1–C5）。体例参照 `docs/superpowers/plans/2026-09-13-v4-p3-ip-pool.md`（同量级里程碑）。

## Global Constraints

抄自 spec 的硬约束，**值逐字一致**；每个任务的要求都隐含包含本节。

- **住宅 HY2 只剩一个监听端口 `:40000`**，整段 `41000-50000` 由 b-ui 自管的 nft 表 REDIRECT 到它（spec §1.2 目标 1）。
- **nft 表必须同时挂 prerouting 与 output 两个 hook（priority -100）**：只挂 prerouting 时，本机发往自身公网 IP 的包不过 prerouting，跳跃失效（spec §2.4，tizi PoC 实测；apernet 的规则同样是 PREROUTING + OUTPUT 两条，`crates/bui/src/modules/portjump.rs:6-9`）。
- **`nft` 二进制是 4.1 的硬前置**（2026-09-16 实测：`bwg-rick` Ubuntu 26.04 **无** `nft`、nftables 包未装；`bwg-tizi` 有 1.1.6）：`bui install` 与 `bui upgrade` 缺 `nft` 时**硬性拒绝**（退出码 2、一个字不落盘、按包管理器打印安装命令），**`bui` 不自动装系统包**（`bui` 全程不装包，`env_probe::pkg_manager_for` 只用于提示）。`nftables.service` 保持 `disabled`、**不 enable 不 restart**（它按 `/etc/nftables.conf` 执行，tizi 该文件第 3 行就是 `flush ruleset`，一 restart 会把 apernet 的 `hysteria_*`、iptables-nft 的 `ip nat` 与我们的 `inet bui` 一起刷掉）。注意 `bui upgrade` 由**旧**二进制执行，所以这道闸门只保护全新装机与 4.1→4.x，**4.0.1→4.1 那一跳拦不住**，由 T18 的演练 preflight 与 T19 闸门 5 守。
- 期望态端口：`ports.hy2_resi = 40000`、`ports.hy2_resi_hop = (41000, 50000)`；兼容段 = `40001 .. 40000 + MAX_SLOTS - 1` = `40001-40007`，由 `system.hy2_resi_compat_ports: bool`（serde default **true**）控制（spec §2.4）。
- 表名与族：`table inet bui`；两条链各两条规则，`counter` 必须在（兼容段命中的**采集**手段——注意它是瞬时流计数，见下条）；注释逐字为 `"hy2 residential hop"` / `"hy2 residential 4.0 compat"` / `"hy2 residential hop (local)"` / `"hy2 residential 4.0 compat (local)"`（spec §2.4）。
- **兼容段下线判据读持久值，绝不读活 counter**（2026-09-16 第一波复核裁决）：nft 的 `counter` 是**瞬时**流计数，`render::nft` 每次重放都先 `flush table`，开机 / `bui nft apply` / watchdog 自愈 / 改端口都会把它清回 0（换具名 counter 也救不了，`flush table` 连 counter 对象一起清）。所以每次重放**之前**先读一次活计数、把增量累加进 `runtime.json`（累计命中数 + `last_hit_at` 时间戳）；`bui status` 打印「兼容段 40001-40007 最近命中 N 次（自 <时刻>）」与 `bui set hy2-resi-compat off` 的 30 天门禁**一律读持久值**。误判方向是危险的那一侧：把仍在用的兼容段判成闲置并关掉，全部还没刷订阅的 4.0 住宅用户当场断联，而兼容段存在的唯一理由就是防这件事。**连续 30 天为 0** 才 `bui set hy2-resi-compat off`，下线前在 CHANGELOG 与面板事件**提前 30 天**通知（spec §2.4）。
- **`table inet` + `type nat` 要求 Linux ≥ 5.2**（2026-09-16 裁决：**钉下限，不出双表**）。4.0 的 iptables 路径没有这道门槛，低于 5.2 的机器整份规则集会被 nft 整事务拒绝、住宅段与兼容段双双不通，而 4.1 的住宅 sing-box 只监听 `:40000` ⇒ 该机住宅用户升级后当场断联。不采用「同时输出 `table ip bui` + `table ip6 bui`」的保兼容方案：规则数翻倍、`rule_count` / 自检 / watchdog 的判据要分叉，而受支持的目标发行版（Ubuntu 22.04+ / Debian 12 / CentOS Stream 9）内核都 ≥ 5.15，低于 5.2 的只有已 EOL 的 CentOS 7（3.10）与 Debian 10（4.19）。落地要求：`bui nft apply` 先 `nft -c -f` 预检、失败时以可操作的中文错误**显式失败**（绝不让跳跃静默消失），T8 的 nft 闸门与 T19 闸门 5 各加一行内核版本核对，`render::nft` 的模块文档第 1 条写明这道下限。
- `password`（写进 sing-box）**= `"{name}:{secret}"`**；`hysteria2://name:secret@host:40000?…` 的 URI 形态与三处 `format!("{username}:{password}")`（`crates/bui-schema/src/render/subscription.rs:208`、`:411`、`crates/bui-schema/src/render/client.rs:331`）**一个字都不用改**（spec §3.1、§7.2）。
- 凭据 `id` = `r` + 三位十进制（`r000`…`r255`）；**迁移用户 `name = username`**，**新发凭据 `name = id`**；`secret`：迁移用户 = 当时的 `credentials.hy2_password`，新发 = 16 字节随机 base64url 无填充（22 字符，**不含 `:`**）（spec §3.1）。
- 池大小 `size_for(n) = clamp(ceil16(2 × n), POOL_MIN = 32, POOL_MAX = 256)`，`n` = 有住宅权益且开 hysteria2 的用户数；空闲 < 20% ⇒ 告警 `hy2_resi_pool_low`；耗尽时建用户**不拒绝**，当场扩容并记 Error 级事件（spec §3.1）。**上限 256 是裁决值**（spec §14 裁决 2：128 凭据已实测 RSS 与 `check` 耗时不涨，256 离已实测点更近；512 属未实测的推断上限）。
- **每次因 §3.5 四件事重写配置时，顺带把全部空闲凭据的 `secret` 重新随机**（`released_at` 清空）（spec §3.1）。
- 回收顺序：释放的凭据先切门到 `deny`、记 `released_at`；再分配时优先「从未用过」的，其次 `released_at` 最早且 **≥ 24 小时**的；池里全是 24 小时内释放的 ⇒ 视同耗尽 → 扩容（spec §3.1）。
- 门（selector）契约：每凭据一个 `gate-<id>`，成员 `["deny", "slot-0-out", …, "slot-7-out"]`（8 个槽预声明，与 `slots::MAX_SLOTS = 8` 同源）、**`default: "deny"`**、**`interrupt_exist_connections: true`**；每凭据**一条**路由规则；`route.final = "deny"`（spec §3.2）。
- `deny` 用指向 `127.0.0.1:1` 的 **socks 出站**，不用 `block`（`block` 出站 1.11 弃用、1.13 删除）；端口 1 本机永不监听，`bui selfcheck` 加一行断言（spec §2.2、§8.3）。
- **裁决：不开 `cache_file`，保持 fail-closed**（spec §14 裁决 1：可用性包线与今天 `auth_http` 相同，而「陈旧放行」会让到期 / 封禁用户在 b-ui 掉线期间照常上网，比短暂拒绝更糟）。sing-box 重启后每个 selector 回到 `default` = `deny`，由 b-ui 重放；重放预算复用 relay 的 `REPLAY_RETRY_BUDGET = 15 s`（`crates/bui/src/modules/residential/health.rs:923`），预算用完仍有差集 ⇒ 停在 `deny` + 告警 `hy2_resi_gate_replay_failed`，60 秒安全网继续收敛（spec §3.4）。
- `hy2-residential.json` **不用 `restart_key`**；它只会因四件事变化：① 凭据池扩容 ② `bui set obfs on|off` ③ 证书轮换 ④ `ports.hy2_resi` / `hy2_resi_hop` 改动。**用户的任何生命周期动作不许触碰本文件**，守门测试断言字节逐字相等（spec §3.5）。
- 新端口常量：`HY2_RESI_CLASH_API = "127.0.0.1:9092"`、`HY2_RESI_V2RAY_API = "127.0.0.1:10086"`，两个面**只监听回环、不设 secret**（spec §2.3）。
- **单元名沿用 `hysteria-residential`**（八处硬编码的锚点）；`hysteria-residential-1..7` 进 `LEGACY_UNITS`（9 项 → **16 项**），`is_managed_unit` 从此对带后缀的名字返回 false，`resi_unit()` 删除（spec §2.5）。
- 单元正文：`ExecStart={bin}/sing-box run -c {base}/hy2-residential.json`、`ExecStartPre=-{bin}/bui nft apply`、`After=network-online.target b-ui-relay.service`、`Restart=always` / `RestartSec=3`、`LimitNOFILE=1048576`、`Nice=-5`、`LogRateLimitIntervalSec=10s` + `LogRateLimitBurst=200`、`MemoryHigh=300M` / `MemoryMax=500M`；**删掉** `Environment=HYSTERIA_LOG_LEVEL=warn`、`Environment=GOMEMLIMIT=200MiB`、`LimitNPROC=512`——**sing-box 不设 `GOMEMLIMIT`**，与 relay 今天一致（spec §2.5、§14 裁决 5：sidecar 实测 65 MB，`MemoryHigh=300M` / `MemoryMax=500M` 已兜底）。
- 计量：`experimental.v2ray_api.stats.users` = **全部凭据的 `name`**；住宅走 `QueryStats(patterns=["user>>>"], reset=true)`（**2026-09-16 订正**：上游 `StatsService.QueryStats` 用的是重复字段 `patterns`，单数 `pattern` 必须留空，否则语义变成「每轮清零全部计数器」；T9 的实现里要有一条测试钉死 `patterns == ["user>>>"] && pattern.is_empty() && reset`），计数器名 `user>>>{name}>>>traffic>>>uplink|downlink`；**直连不变**，仍打 `/traffic?clear=1` + `/online`，`stats_ports` 收成 `[9999]`、`resi_stats_ports` 删除（spec §5.1）。
- 在线数 = `GET /connections` 里按 `rule` 字段的 `auth_user=<name>` 归组的连接条数（`metadata` 里**没有** user 字段）；踢用户 = 门切 `deny` + 逐条 `DELETE /connections/{id}` 兜底（spec §5.2）。
- **只有随发布分发的那一个 sing-box 自建**（为了 `with_v2ray_api`）；`SINGBOX_CHECK_MINORS="1.12 1.13"` 那两个继续用上游二进制（spec §5.3）。
- **内核身份 = 版本号 + 资产 sha256**（2026-09-16 裁决，**发布阻断级**）：自建 sing-box 与官方同版本同名（两者 `sing-box version` 都打 `1.14.1`，因为 ldflags 里就是 `-X …constant.Version=1.14.1`），而内核身份今天**只比版本号字符串**（`diff.rs` / `upgrade.rs::plan_upgrade` / `install.rs` 三处）⇒ v4.0.1 已装官方 1.14.1 的机器上 `InstallBinary` **永远不会被计划**，自建二进制装不上去，`bui upgrade` 还会打印「sing-box 1.14.1（已最新）」；于是 `hy2-residential.json` 每轮 `sing-box check` 必然 FATAL（`v2ray api is not included in this build`）、永不落盘，而同轮单元已指向它、旧 `config-residential*.yaml` 已删 ⇒ **住宅 HY2 永久崩溃循环、没有自愈点**。三处一律改走 `kernels::kernel_build_differs`（版本不同、或盘上 sha ≠ manifest `artifacts.<name>-linux-<arch>.sha256` 即重装），与 `bui` 自己的 `bui_build_differs` 同判法——我们给自家二进制做对了、给内核漏了。注意 **T2 的「Tags ⊇ 官方 + with_v2ray_api」硬断言守不住这题**：它守的是发布物，不是机器上装的是哪一份；P-A 之后两者才闭环。
- **对账顺序：内核二进制先于带 `Verify` 的文件**——校验必须用**将要运行该配置的那个二进制**（今天的顺序是反的：拿旧二进制校验新二进制要跑的配置，xray 大版本改字段时会「校验过、上线崩」）。且**带 `restart` 的文件校验失败或写失败 ⇒ 该单元本轮的单元文件与重启一并搁置（held）**，绝不让「单元已换、配置未落」同时发生。
- 自建失败语义（硬要求）：上游 clone 失败、构建失败、`Tags` 不达标、sha 不可重现、`check` 不过——**任何一步失败 ⇒ 工作流红、锁不动、不开 PR**；`release.yml` 永远只用锁里的版本，**发布保持上一版**，GitHub 的失败通知就是告警。**绝不因上游改动阻塞发版**（spec §5.4 第 8 条）。
- 自建二进制的 `sing-box version` 的 `Tags:` 必须 **⊇ 官方同版本归档的 `Tags:`，且含 `with_v2ray_api`**，不满足即红（spec §5.4 第 4 条）。
- **`nodes_for` 签名不变**（`nodes_for(&User, &NodeParams, &Residential)`），三种订阅与 `render::client` 的签名不变；`render::relay::config`、`render::xray::config`、`v3::import` 签名不变（spec §13 C1）。
- **住宅 HY2 节点的 label「HY2住宅」不能改**：profile 名由 用户名 + label 算出，改了会新增节点、旧节点变死节点（`bui-c` rc1 源码 `cli.rs:515-560` 原文）⇒ `crates/bui-schema/src/nodes.rs:145` 的 `"HY2住宅"` 字面量**不许动**（连空格、连全半角都不许）（spec §7.4 约束 1）。
- **v3 golden 只允许新增**：`crates/bui-schema/tests/fixtures/v3/expected/` 下任何文件不许改动一个字节；三种订阅对现有 fixture 的输出必须逐项等于今天的 golden（spec §10 阶段 1 判据）。
- 8 槽下**每个用户的住宅 HY2 端口与区间完全相同**（`40000` + `41000-50000`），守门测试钉死（spec §10 阶段 1 判据）。
- **旧订阅兼容四条不变量**（spec §7.5，**客户端不会自动刷新节点**：`bui-c` 取节点只有 `crates/bui-c/src/cli.rs:878` 与 `:3005` 两处，每分钟的 `check` 与每日自动更新都不取）：① HY2 认证串仍是 userpass 形式的 `username:password`（客户端 `crates/bui-c/src/parse/node_uri.rs:41-53` 就是这么发的；sidecar PoC 已验证 sing-box 的 `users[].password` 必须写成 `名:密码` 才互通 ⇒ 天然满足）；② obfs 密码、SNI 与证书不变；③ `41000-50000` 与 `4000x` 的 UDP **全部**转发；④ 按用户粘槽的出口路由语义不变。任一条破了，「从不重新导入」的机器就是断网——REDIRECT 只兜住端口一项。端到端验收在 **T19**（用 rc 客户端渲染出的 `config.json` 原样连 4.1 服务端）。
- 到期 / 封禁语义变化写进文案：「已停用 / 已到期：**住宅 HY2 客户端仍会显示已连接，但所有请求会被拒绝**；直连节点在连接时即被拒绝。」（spec §6）

### 第一波复核裁决（2026-09-16，T1 / T4 / T6 回来之后）

除上面两条已写进 Global Constraints 的（counter 持久化、内核下限 5.2），另有六条裁决，后续任务按此执行：

1. **自建的 ldflags 取上游 `release/LDFLAGS`，不在脚本里硬写。** 计划原先给的 `-s -w -buildid= -checklinkname=0 -X …constant.Version=` 漏了上游的另一半 `-X runtime.godebugDefault=multipathtcp=0,tlssha1=1`，而 `Tags` 断言查不出 godebug 差异 ⇒ 自建二进制的 MPTCP 默认与 TLS 是否接受 SHA-1 会与官方归档不同。改为从 clone 出来的 `release/LDFLAGS` 读取并只追加 `constant.Version`，让与官方的行为一致是**结构性**的而不是靠人抄。
2. **锁里的 `go=` 必须是被强制的输入，不是记账。** `build-singbox.sh` 增 `--go <go1.x.y>`：给了就 `GOTOOLCHAIN=$GO_PIN` 跑 `go version` / `go build` 并断言探到的版本等于传入值（不符退非 0），没给才退回 `auto`（供 pin 时发现版本）；`fetch-kernels.sh` 的 `build_kernel` 解析 `go=` 并透传 `--go`。否则锁里的 sha 只在「宿主 Go ≤ 锁里那版」的机器上可重现，宿主 Go 一升就必然 sha 不符退 4，且与工具链漂移无法区分。
3. **构建器 stub 必须把 argv 落盘再断言。** 第一波给 `build:` 解析加的断言完全抓不住解析逻辑（stub 把 `--repo/--version/--arch/--tags` 全 shift 丢掉、只认 `--out`），解析回归只会以「sha 不符」的形式出现。stub 里 `printf '%s\n' "$*" >> "$ARGV_LOG"`，再断言 repo / version（不带 `v`）/ arch / tags 逐项出现，pin 侧断言 amd64 与 arm64 各被调一次。
4. **commit trailer 的 `Claude-Session` 由每个实施会话盖自己的**，不照抄计划正文里那个 id（符合 harness 的归属规则）。计划第 70-73 行那段的 session id 仅作格式示例，T2–T20 的复核不要再按「逐字照抄」挑这一条。
5. **hysteria 轨道漂移（锁 2.12.2 / 轨道解析 2.12.3）另案，不并进 4.1 的任何任务。** 它在第一波改动之前就已存在（`pin-kernels.sh --check` 早就报它），且 `ci.yml` / `release.yml` 对漂移只 warning 不判红。所以 T1 只改 `sing-box target` 两行、不跑全量 `--write`（会顺带把 hysteria 顶到 2.12.3），锁头注释的「生成时间」保持原值并加一行说明那两行是回填的。
6. **`CLAUDE.md:89` 那句进 T15 的文档清单。** 原文「`kernels.lock`（上游归档的精确版本与 sha256）」在 T1 之后不再全真（`sing-box target` 两行的 sha 是我们构建出的裸二进制、URL 列是 `build:` URI），T15 回写时一并改掉，否则它是无人认领的漂移。

### 第二波裁决：P-A / P-B / P-C / P-D（2026-09-16，发布阻断级）

来源：T8 的复核发现「首轮对账 `hy2-residential.json` 校验 FATAL ⇒ 住宅崩溃循环最多 10 分钟」，交独立裁决者复核后**量级被纠正为永久停机**（自建 sing-box 因版本号相同而根本装不上，见 Global Constraints 新增的第一条）。四条一起落，**前三条都排在 T8 之前或同批**：

- **P-A 内核身份改 sha256**：新增 `kernels::kernel_build_differs(host, bin_dir, name, want_version, want_sha256)`（版本不同 ⇒ true；相同则读盘上二进制比 sha，读不到 ⇒ true），替换 `reconcile/diff.rs`、`commands/upgrade.rs::plan_upgrade`、`commands/install.rs` 三处。判据四条：① FakeHost 盘上 `bin/sing-box` = 官方字节且 `version` 打 `1.14.1`、artifact 要求同版本但 sha 是自建的 ⇒ 计划里有 `InstallBinary`；② 字节换成自建的 ⇒ `unchanged`；③ `plan_upgrade` 同版本异 sha ⇒ kernels 列表里出现 sing-box；④ 现有那条把 `bin/xray` 种进假机器的用例要把字节改成 sha 匹配的。
- **P-B 对账顺序**：`InstallBinary` 整块移到「写文件」之前；nft 表那一步留在原位（它要求「二进制之后、停遗留单元之前」）。判据：用会真写 FakeHost 的 installer（装完才让 `sing-box check` 成功），断言 `write:bin/sing-box` 先于校验、json 落盘、`verify_failures` 空、`restarted` 恰含住宅单元一次。**核实过不碰早返回**：`--dry-run` 在任何步骤之前就返回；`upgrade --rollback` 根本不调 `apply`。
- **P-C「held」——拆成独立提交，先于 T8 合并**：这是 **4.0 就存在的普遍缺陷**，不是 4.1 个案。`apply` 按 Change 种类分步、各步互不知情：文件校验失败只 `continue` 掉那一个 `WriteFile`，同一单元的 `WriteUnit` 照写、`InstallBinary` 照把单元塞进 `restart`、最后一律重启，**没有任何一处按「该单元的配置这轮落了没有」做门控**。4.0 至今良性（旧配置仍在盘上且合法，最坏一次无意义重启），4.1 第一次致命是因为它是第一个把一次转换摊在五种 Change 上的 artifact（写新配置 + 换单元 ExecStart + 删旧配置 + 停 7 个遗留单元 + 落 nft 表），「部分落地」第一次等于停机。修法只补两项：带 `restart: Some(u)` 的 `WriteFile` 校验或写失败 ⇒ `u` 记入 `held`，跳过它的 `WriteUnit` 与重启，各记一条 note。提交信息用 `fix(reconcile): 配置校验失败时搁置该单元的单元文件与重启`，只碰 `apply.rs` 与其测试，4.0.x 可 cherry-pick。**明确不补**第 9 步停遗留单元、第 11 步删文件、nft 表那一步的门控——要给 `Absent` / `UnitState` / `NftTable` 加依赖边（仅 `Artifact::Absent {` 就 20 处构造 + 5 处模式匹配），不是本期的量。
- **P-D `units_for_binary`**：`hysteria` 收成只有 `hysteria-server`，`sing-box` 加上 `hysteria-residential`（= T8 复核的 P1）。连带：`rollback()` 也用这个映射，加了之后回滚会多重启住宅单元一次，而 spec §9.1 要求回滚先 stop 它再删表 —— **T15 落 `rollback` 时注意别重启两次**。

**残余暴露面（记进 4.1.x backlog，不修）**：有了 P-C 之后，4.0.1→4.1 那一跳里若自建 sing-box **下载失败**，终态是 degraded 而不是停机——nft 表已把整段导到 `:40000`，槽 0 的 apernet 进程仍在 `:40000` 服务（全员连得上，槽 ≥ 1 的用户出口 IP 错），install 失败进 `errors` 并被 `bui status` 点名，下一轮下载成功即自愈。没有 P-C 则是崩溃循环。

而 4.1 之前「HY2 鉴权不看槽」（spec §7.6 事实 3）意味着旧槽端口的节点仍然能连、只是从另一个住宅 IP 出去，
所以客户端那一版必须先带上「同账号重复节点**不自动合并**，只提示或经菜单确认」，否则用户会在看不见的地方被换出口。
tag 是唯一的闸门，门禁就守在这里。

骨架（照 `check-version.sh` 的风格：`printf` 中文、`ROOT` 从 `BASH_SOURCE` 算、退出码显式）：

```bash
#!/usr/bin/env bash
# 发布 tag 门禁：受管 tag 前缀的必需提交必须已经是 HEAD 的祖先。
# 用法：check-release-gate.sh <tag> [--warn] [--repo <dir>] [--required <file>]
# 退出码：0 通过 / 不在门禁范围 / --warn 下不过；2 用法错误；3 门禁不过。
set -uo pipefail
LC_ALL=C
ROOT=$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)
TAG=""; WARN=0; REPO="$ROOT"; REQ=""
# …参数解析：第一个非选项参数是 TAG，未知选项退 2
[[ "$TAG" =~ ^v[0-9]+\.[0-9]+\.[0-9]+(-rc[0-9]+)?$ ]] || { printf '用法：%s <v x.y.z[-rcN]> …\n' "$0" >&2; exit 2; }
REQ="${REQ:-$ROOT/scripts/release/required-commits.env}"
[[ -f "$REQ" ]] || { printf '门禁清单读不到：%s\n' "$REQ" >&2; exit 2; }
minor="${TAG%.*}"                     # v4.1.0-rc1 → 先剥 -rcN 再取 v4.1
key="GATE_${minor//./_}"              # v4.1 → GATE_v4_1
sha=$(awk -F= -v k="$key" '$1 == k {print $2}' "$REQ" | tail -1)
```

分支与文案（全部中文，**退 3 的三种各一句「怎么办」**）：

| 情形 | 输出 | 码 |
|---|---|---|
| `key` 不在清单里 | `tag <TAG> 不在门禁范围（清单里没有 <key>），放过。` | 0 |
| `sha` 是 `pending` / 空 | `发布门禁未配置：<清单> 里的 <key> 还是 pending。填上那条提交的完整 sha 再打 tag（门禁是 fail-closed 的，不许空过）。` | 3 |
| `git cat-file -e "$sha^{commit}"` 失败 | `发布门禁不通过：提交 <短sha> 在本仓库里找不到（浅克隆？CI 的 checkout 要 fetch-depth: 0）。` | 3 |
| 不是祖先 | `发布门禁不通过：4.1.x 需要的提交 <短sha> 不是 HEAD（<短head>）的祖先。先把 bui-c「同账号重复节点不自动合并」那条改动合进本分支再打 tag（依据：spec §7.6 事实 3）。` | 3 |
| 是祖先 | `发布门禁通过：<key> 的提交 <短sha> 已在 HEAD（<短head>）里。` | 0 |

`--warn`：把退 3 的那三种改成 `printf '::warning::%s\n'` 到 **stdout** 并退 0（GitHub 注解要走 stdout；
退 0 之前那行文案一字不改，方便 grep）。`--repo` 一律经 `git -C "$REPO"`，所有 git 调用都加它。
