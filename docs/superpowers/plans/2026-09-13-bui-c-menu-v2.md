# bui-c 菜单 v2 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 spec 给 bui-c 数字菜单加删除节点（含墓碑名单与 `bui-c delete`），把 [5] 连接检查补到 v3.6.2 的信息量，交互终端里清屏重画并加「上次」行，按终端宽度排版，重排主菜单并让检查更新先显示版本再确认，加进程锁与中断收敛；P1 再加卸载清单、节点测速、巡检失败行与 `bui-c test`。

**Architecture:** 渲染仍是 `menu.rs` 里零 ANSI 的纯函数，多一个宽度（和行数）参数；菜单循环在 `cli.rs`，每个动作返回 `Outcome`，由循环决定清屏、停顿与「上次」行。删除的规划是 `delete.rs` 里的纯函数，执行编排在 `cli.rs`（锁外装内核 → 拿锁 → 比对快照 → 预检 → 先数据面后落盘 → 失败回滚）。系统交互全部经 `Sys` / `Net` 两个 trait，测试只用 `FakeSys` / `FakeNet` / `Scripted`。

**Tech Stack:** Rust（MSRV 1.85，edition 2021），现有依赖不变：clap 4、reqwest 0.12 blocking（socks）、serde / serde_json、sha2 / hex、nix 0.29（`user`）、time、tracing。

**Spec（权威）：** `docs/superpowers/specs/2026-09-13-bui-c-menu-v2-design.md`。**§0.2（R1–R16）优先于正文与屏幕稿**；本计划每个任务注明要读的章节。屏幕稿只作示意，行宽以容量口径（§2.2）与守门测试为准。

## Global Constraints

- 不改根 `Cargo.toml`、不改 `Cargo.lock`、不引新依赖。锁用 `nix::fcntl::Flock`（现有 features 可用）；终端尺寸用 `unsafe { nix::libc::ioctl(STDOUT, TIOCGWINSZ, …) }`，全 crate 只此一处 unsafe，附 SAFETY 注释；账号指纹用已有的 `sha2`。
- `menu::render_*` 零 ANSI；清屏只发 `"\x1b[H\x1b[2J"`（不发 `ESC[3J`），只在 stdin 与 stdout 都是终端时由 `Ctx::clear_screen` 直接写 stdout，不经过 `emit`，`ctx.transcript` 永远不含 ESC。
- 菜单只认数字直选（全角数字折半角），文案全中文，新文案用「」，不用 “” 与 ·。固定文案按容量口径（歧义字符算 2 列）≤ 59 列；40 列下编号、名字、能不能操作必须可辨认。
- 凭据不进 argv、不进日志、不进错误文本：新增的 `Net` 方法一律经 `request_error`（错误里不带 URL）；测速的 socks 认证用 `Proxy::basic_auth`，不拼进 URL。
- `bui-c check`（timer）路径不加任何第三方请求；检测站只在菜单 [5]、`bui-c test` 与 [9] 里用。
- 菜单里的破坏性确认不认全局 `-y`；会断网的删除（Switch、Empty）要输入 `yes` 或「是」。
- 单元测试只用 `FakeSys` / `FakeNet` / `Scripted`，不跑 systemctl、不写 /etc、不联网（包括 127.0.0.1 回环）。
- 公开仓库：代码、测试、注释、commit 只用示例值（`rick-node.example-a.net`、`tizi.example.test`、`temp.example.test`、`panel.example.com`、`示例用户甲`、`示例专用名`、IP 用 `203.0.113.x`），不写真实域名、IP、面板用户名。
- 一个任务一个 commit，中文标题照 §13.0 表；commit 信息末尾加 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`；`git add` 只加本任务改动的文件；不 `git commit -a`、不裸 `git stash`、不 push。
- 每个任务完成的门禁（全绿才算完）：
  - `cargo fmt --all -- --check`
  - `cargo clippy -p bui-c -p bui-schema --all-targets -- -D warnings`
  - `cargo test -p bui-c`（T14 另跑 `cargo test -p bui-schema`）
  本机 macOS 可以直接跑这三条；`crates/bui` 在 macOS 编不过，不要跑 `--workspace`。
- 行号以 HEAD `38e5d79` 为准（bui-c 部分与 500c786 相同）；代码风格照周围：中文注释、测试写在同文件的 `mod tests`、helper 复用 `ready` / `two_nodes` / `with_unit` / `names` / `nodes_payload` 等（见 `cli.rs` 测试模块）。
