# 出口选择与数据面激活分离

## 范围与目标

只面向固定的 sing-box 1.14.2。Rust 继续拥有期望态、出口决策和激活记账，协议由内核实现。基于住宅策略端点拓扑，本阶段解决“保存选择也会重启全体连接”和“配置写盘即误认为已加载”这两个相连的生命周期问题。

连接的出口选择与配置结构属于两种不同变化：Clash 热切已经完成的选择持久化，只更新冷启动默认值；监听、上游地址/凭据、路由/DNS、自动黑名单、端口能力或槽绑定变更，需要重新激活。后者目前仍会中断 relay 连接，本阶段不宣称无损配置更新。

## 激活凭据

relay 的结构指纹只移除 `type=selector, tag=resi-pool` 的 `default`。其余字段全部保留，尤其是各槽默认出口、成员列表、供应商凭据与策略。配置文件依旧写入持久选择作为冷启动 fallback；内存中的选择及重启重放保持既有 UUID 语义。

对账器对有结构指纹的文件同时记录：

- 最近一次成功激活的结构指纹。
- 最近一次被确认写入的完整文件内容指纹，用来识别外部改动。

只有已确认的结构相同、当前文件仍是已确认的文件时，才允许只写新的默认值而不重启。缺少记录（首次迁入本机制）、文件漂移或结构变更都保守地校验并重新激活；不能用单独一个缓存 key 猜测运行进程加载了什么。

必须激活的文件在成功写入后暂存候选记账，只有服务确实运行后才确认。同一服务的其他文件失败、激活失败或回滚，只能保留旧确认，不得提交新结构。文件字节已经相同但激活未确认时，下一轮仍需重试。守护进程自重启仅发出请求，不提前确认加载结果。

首次迁入时，现有 Xray 和 relay 的 runtime 没有完整文件指纹，即使文件相同也会保守校验并重新激活一次；后续对账收敛。这个一次性中断须计入部署窗口，不能宣传为升级本身无损。当前生产 artifact 不给 b-ui 自身使用 restart_key；如未来引入，需单独设计启动后确认，不能把自重启请求当作已完成。

这仍是受管进程下的激活记录：不能据此宣称能识别所有外部进程操作或断电时刻，也没有把多文件/二进制替换变成原子事务。

## 验收

1. 真实 renderer → plan → apply：保存 A→B 选择后，文件 default 为 B，零 systemd 动作，重复对账零变更。
2. 供应商凭据、规则、槽或监听变化依旧触发激活；不能为了少重启忽略这些配置。
3. 相同文件但未知/过期激活记录必须重试；已确认后零变更。
4. 部分写入失败、重启失败并回滚时不确认候选；外部改写不能被匹配的结构缓存掩盖。
5. 回归 Xray 的热用户更新和真实 sing-box 1.14.2 数据流测试。

## 后续完整阶段：配置代际发布

当前审查还确认了发布事务的缺口：内核安装失败后其他配置仍可能继续应用；内核成功替换后配置校验失败无法恢复旧二进制；部分 start 路径与 restart 的搁置条件不同。这些应以一个完整依赖事务处理，不分散增加版本兼容条件。

目标数据路径为稳定入口/selector → 不可变出口策略代。现有回环策略端点可以迁入代际后端，复用现有一次回环，不再额外叠一层。每代绑定配置内容、供应商 UUID、代号和端口所有权。

实施顺序：准备 1.14.2 二进制及该代配置 → 用同一候选内核校验 → 离线/连通探测 → 将新连接切到新代 → 旧流排空 → 回收。任一步失败都保留旧代；崩溃恢复根据持久事务记录判断正在运行和待清理的代，不能只看文件存在。端口、FD、内存和同时存活代数必须有上限，未排空端口不得复用。

第一批代际更新仅覆盖出口策略与供应商凭据。公共入站、槽拓扑、分流主结构变更仍使用维护重启。验收必须包含准备失败、切换失败、旧流持续传输、同 UUID 跨代日志隔离、资源耗尽和中途进程退出恢复，之后才考虑部署。
