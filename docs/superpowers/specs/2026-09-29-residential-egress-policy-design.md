# 住宅策略跟随实际出口

## 问题与范围

Rust 控制面继续保留。上一轮稳定性修复在 PR #1，本阶段基于其提交，独立审查。此前真实 renderer + sing-box + 回环模拟上游已经复现：全局配置选择 A 时，槽 B 仍受 A 的 `ports_allowed` 和自动黑名单影响；B 自己的自动黑名单不生效。仅按初始槽限定规则也不够，因为 Clash 借用 B → A 不会改配置。

本阶段将出口特有策略放到选择之后执行。保留既有人工 pin、私网/本机例外、split/global 语义和混合 HTTP/SOCKS 池的保守 UDP 降级。暂不改状态格式、订阅、凭据门、内核协议实现或每轮健康巡检规则。

## 数据路径

```text
HY2 gate / Xray → slot-i SOCKS 入站 → 公共规则 → slot-i-pool selector
  → resi-N SOCKS 回环出站 → resi-policy-<UUID> 入站
  → 该 UUID 的自动黑名单和端口限制 → resi-egress-<UUID> 真实上游
```

`resi-N` 仍是 Clash selector 的成员名称，运行期选择接口保持兼容。策略入站只绑定回环；资源由 `bui-schema::relay_policy` 集中定义，2180–2187 对应最多 8 条上游。真实出口采用规范 UUID 标签，不把数组位置当长期身份。策略入站必须有终结路由，不能回落到 selector 造成循环。

`Store::open/create/update_as` 在渲染或写盘前检查每个分组的上游数量。旧版导入或手工状态文件超过 8 条时明确拒绝加载/保存，保留原文件，不自动截断；升级前应备份并将此类配置整理至支持范围。这样避免直到对账才因端口越界 panic，但不承诺自动接管超容量的历史配置。

人工 pin 是公共配置，继续在槽入口全局生效。自动黑名单的规则和端口白名单仅绑定各自策略入站。DNS 不再因全局默认上游的自动规则污染其他槽。客户 UDP/53 直连、混有 HTTP 时 UDP/443 拒绝及其他 UDP 直连维持原约定。全 SOCKS 时在策略层先匹配自动域名规则，再做 IPv4 解析，随后再次检查私网，最后进入真实供应商。内部 `dns_resi` 的 UDP/53 detour 直接进入真实出口，保留旧版绕过客户分流规则的语义，不能因增加回环而悄悄变为直连 DNS。

已有连接保留旧上游，新连接在 selector 切换后同时采用新上游和新策略。切换不写配置、不重启内核。增加/删除上游或修改策略仍会改变整份 relay 配置，需要既有 reconcile 重启；本阶段不声称实现配置更新无损排空。

## 嗅探与故障归因

回环 SOCKS 传输不携带第一层嗅探元数据。入口保留分流需要的 sniff，策略层只在有自动域名规则且目标没有域名时再次嗅探。已知 FQDN 不再等待第二轮首包。实际目标保持客户端提供的地址，不根据不可信 Host/SNI 动态改写目标。IP-only 且服务器先发数据的连接仍可能经历第二轮 sniff 等待，必须在验收中量化披露；不能只跑 JSON 校验。

内部真实出口日志直接携带 UUID。旧位置成员、池选择器形态只用于仍运行旧拓扑的兼容路径。判断拓扑必须读取正在运行的 Clash API；不能拿期望态推测已生效配置。新拓扑外层回环转发产生的派生失败不得再次参与学习和借用，否则会将旧连接的故障算到已切换的新上游，或重复计数。批次已有 UUID 事件时只使用 UUID 事件，避免回滚后的旧拓扑判断复算同批外层错误。拓扑无法确认时宁可放弃含糊证据；明确 UUID 事件仍可处理。未知或已删除 UUID 不归因到其他上游。同 UUID 覆盖凭据/地址后的跨配置代际归因不在本阶段解决，后续仍需 generation/epoch。

## 验收与边界

1. 两上游不同端口能力、不同自动域名/端口规则，互不污染；人工 pin 仍全局生效。
2. B → A → B 热切，新连接跟随对应策略，旧 TCP 流继续收发；内核 PID 不变。
3. 全 SOCKS 的 UDP 双向通信、域名解析和同会话地址变化仍正常；混池规则保持。
4. raw UUID 错误能正确归因；外层派生错误不触发重复事件，旧拓扑兼容不退化。
5. 唯一目标为锁定的 sing-box 1.14.2 发布内核；配置校验和全部实际 TCP/UDP 回环测试均在该内核执行，不保留旧 minor 适配矩阵。
6. 量化额外转发层的短连接分位延迟、server-first 等待、长流吞吐与 FD；记录环境，不把回环成绩当作公网 SLA。

主要风险是多一次本地 SOCKS 握手、额外文件描述符、重复嗅探和 UDP 会话包装。上线前必须通过真实内核验证。未来“准备新配置 → 切新流 → 排空旧配置”的双代 relay 属于另一阶段，不在本 PR 中混入。

上游行为参考：[SOCKS 出站](https://sing-box.sagernet.org/configuration/outbound/socks/)、[路由动作与嗅探](https://sing-box.sagernet.org/configuration/route/rule_action/)。运行语义以固定 1.14.2 发布内核的实际测试为准。
