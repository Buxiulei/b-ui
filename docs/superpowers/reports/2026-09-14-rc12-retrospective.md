## 0. 结论

主理人问了两个问题：时间去哪了、是否过度编程。答案：

- **时间主要耗在一项不在需求里的改动上**——哨兵「借用后验证目标可用」是审查发现的缺陷，被塞进 rc12，然后主会话把它的设计改了三次、停掉重派两次。三次外部中断（两次恰好死在合并步）把订阅 token 四路分支的合并拖成第三次尝试，把返工再翻了一倍。
- **过度的是两处，不是全部。** 过度：借用验证进 rc12；删上游报名单做成三组分类 + 精确子集判据。不过度：审查抓到的六个真缺陷，每个放出去都是生产事故（§2.2）。审查深度本身不是问题，问题是「审查发现 → 顺手修进当前版本」这个反射。

三类原因分开看（§3）：外部中断、主会话的设计错误、范围蔓延。每类给的都是可执行的做法，汇总成派单模板规则（§4）。rc12 已冻结（§5）。

## 2. 过度工程自查

### 2.1 认定过度

1. **哨兵借用后验证进 rc12。** 不是主理人要的功能，是审查中发现的缺陷，本可留 4.0.1。三个设计错误（§3.2）全出在这一项上——它不进 rc12，这些返工一个都不会有。
2. **删上游报受影响名单。** 最终写成三组分类 + 精确子集判据、+779 行，只为一条提示信息。有用但太重。合理上限：一份名单、一次模拟真删（`b38579f` 那一版已经够）。

### 2.2 不算过度：审查抓到的真缺陷

| 缺陷 | 放出去的后果 |
|---|---|
| 轮换「先摘再加」在 b-ui / xray 重启后也作用于未改动的健康 Reality 用户；摘成功而加失败就把好用户踢出内核，等 60 秒安全网 | 一次重启让无关用户断连一分钟 |
| 面板重置用「清空当前用户」当标记，紧接的刷新失败让弹窗永久停在已作废链接上，5 秒一轮的自愈通道被自己关掉 | 运维复制走一条死链接发给用户 |
| `scripts/ops/upgrade-drill.sh` 按用户名取订阅比对前后哈希；token 化后取到 404、两次都记空串哈希，静默判「无漂移」 | 升级演练假绿 |
| `scripts/m1-acceptance.sh` 把订阅 token 放进 curl 命令行，同机 `ps` 可见，脚本自己写着「凭据绝不进 argv」 | 与本次安全修复的目的相反 |
| Caddy 默认 logger 与 80 端口跳转的 `Location` 头会漏 token（`log_skip` 挡不住）；调试日志级别下 `TraceLayer` 的 span 打完整 URI | 新凭据从日志再漏一遍 |
| 一份审计文档仍留着真实机房 DNS 网段前缀 | 公开仓库脱敏不完整 |

### 2.3 分界线

审查产出的是「发现」；修不修、修进哪个版本，由冻结规则和主理人决定，不由审查者顺手决定。把这条线划清，审查可以继续深，rc 不会继续胖。

## 3. 三类原因，各自下次怎么少花

### 3.1 外部中断（额度 ×2、API 500 ×1）

三次都杀了正在跑的代理；两次额度耗尽正好在合并步，四路分支的合并因此做到第三次。中断本身不可控，可控的是每次中断的损失面。

- **合并逐分支落地，不攒批。** 合一个分支就完成一个（merge commit 落到本地 v4），下一个分支再起。四路一起合到一半被杀，等于四路都没合。
- **待合队列写进文件，不放在会话记忆里。** 分支名、已过审的 SHA、合并顺序，落 `docs/superpowers/plans/` 对应计划的「待合」段；中断后 part2 只读这个文件加 `git log --oneline v4..<分支>`，不 resume 旧会话。
- **额度临近时只做可丢弃的活。** 审查、写文档可以随时断；合并、发版、真机切换不开。会话额度与周额度都是可预见的，不该在它们的边上做合并。
- **API 500 不可预见，只能靠前两条把损失限在一个分支内。**

### 3.2 主会话的设计错误（全部在哨兵借用验证上）

| 错误 | 事实 | 下次的规则 |
|---|---|---|
| 候选按网关主机归组 | 采纳了另一会话的建议。生产池是同一网关主机上的多个静态端口、每端口一个出口 IP；按主机归组会把「单个出口 IP 死」判成「整组死」，拒绝借用，功能作废，演练判据二、三必红 | **归组与去重的粒度必须等于证据的粒度。** 探测是逐端口做的，归组就只能逐端口。采纳外部建议前先把生产形态用一句话写下来（「同一网关多静态端口，每端口一个出口 IP」），再拿建议去对 |
| 延迟只看快路 | 以为死候选 TCP 超时 3 秒就是上界；`probe_quick` 在网关 TCP 通过后还走 HTTP（8 秒 + 5 秒 + 逐地址的 407 补判），挂死场景实测 28.38 秒，两条 SLA 全破 | **写延迟预算前把被调函数每条 return 路径的超时相加。** 快路不是上界，最慢的那条分支才是 |
| 「未能确认」语义定反 | 第一版让「判原上游无结论」不借用；最常见的故障形态恰是网关活着、隧道挂死，于是哨兵永久空操作 | **先问失败路径的终态，再问延迟。** 设计评审第一句是「每条失败路径结束时系统在什么状态」；「无结论」也是一条失败路径，必须落在处置而不是空操作 |

三条有一个共同点：都能在派单前用一张「失败路径 → 终态 → 延迟」的表逼出来。这张表进模板（§4 第 1、5 条）。

### 3.3 范围蔓延

- 借用验证：审查发现 → 直接进 rc12。规则：**审查发现的非需求缺陷默认进下一个补丁版**，进当前冻结版本要主理人点头。
- 删上游名单：一条提示信息 → 四轮迭代成分类系统。规则：**一条提示信息的实现上限是一次 commit、一份名单**；要加第二组分类就先停下问「谁会看这组」，没人看就不加。
- 两处的根子一样：派单时没写目标版本。规则：**每张派单写明目标版本（rc12 / 4.0.1）与该版本是否冻结**，实现者不得自行扩到冻结版本。

## 4. 进派单模板的规则

逐条可执行；前八条来自主会话，后六条是本文补的。

1. 涉及切换、回滚、重试的改动，必须为每条失败路径写出终态，并且每条终态有断言。「无结论 / 未能确认」也算一条失败路径。
2. 断言落在用户或运维真会看的出口——事件（`incidents`）、`--json`、状态行——不只钉内部结构体。
3. 断言用户可见文案时只钉可操作的那一半（「已借用槽 2」），不钉解释性的那一半，文案改措辞不该让测试红。
4. 延迟预算必须核对被调函数的全部分支，把每条 return 路径的超时相加得上界；只看快路的预算不接受。
5. 「两边都留」型合并冲突，先看 HEAD 侧末行是不是右花括号，再决定保留顺序；别按文本顺序拼。
6. 去重与归组的粒度必须与证据（探测）的粒度一致：逐端口探测就逐端口归组。
7. 额度中断后按 git 状态起 part2（`git log --oneline v4..<分支>` + 待合队列文件），不 resume 旧会话。
8. 审查发现的非需求缺陷默认进下一个补丁版，不进当前冻结的版本；例外由主理人明示。
9. 每张派单写明目标版本与冻结状态；实现者返回时附「本分支只含派单范围的 commit」的核对（`git log --oneline v4..<分支>` 原文）。
10. 凭据不进 argv：脚本里的 token / 密码只走 stdin、`-K -`、环境文件；审查时 `grep -n 'curl' <脚本>` 逐行看。
11. 免鉴权端点改路径或参数后，所有按旧路径取数的脚本（演练、验收）同步改，且空结果必须判 FAIL——空串与空串相等不算「无漂移」。
12. URL 里新增或改动敏感段时，逐层核对会打印 URI 的地方：Caddy 默认 logger、跳转的 `Location`、`TraceLayer` span、access log；只改自家 logger 不算完。
13. 一条提示信息的实现上限是一次 commit、一份名单、不新增分类；超出就拆到下一版。
14. 采纳别的会话或审查者的设计建议前，先用一句话写下生产形态（拓扑、槽位、上游形态），拿建议对一遍再采纳。
