## 如何核对保留材料

在具备原文件的受控环境里，按索引的 `name` 定位文件，核对字节数和 SHA-256；不要根据相近名字、旧日期或相同版本号替换材料。`rust_source_map_sha256` 与归档字节摘要分开使用。

```bash
# macOS 示例；FILE 指向手中受控保留的实际文件。
shasum -a 256 "$FILE"

# Linux 示例。
sha256sum "$FILE"
```

重新构建或运行实验前，记录实际工具链、目标架构和源码指纹，使用明确的测试目标；成功退出但执行 0 个目标测试不算通过。测试方法和结果边界见[验证台账](verification-ledger.md)。

## Docker 与编译资源约束

此前本机 Docker 虚拟机内存占用过高，已将设置降到 4096 MiB / 4 CPU。最近读回的 Engine MemTotal 为 4,109,787,136 字节，两个 BUI 构建容器均已停止；这些是记录时的状态，接手时需重新核对。

- 按阶段仅启动一个 BUI builder；原生 builder 上限 2 GiB，交叉构建 builder 上限 3 GiB，均为 2 CPU，容器 memory-swap 与 memory 相同。
- Cargo 构建串行，jobs=1；x86_64-musl 构建明确指定 target，避免生成一套误用的本机目标输出。
- 每批测试用冻结源码和独占临时目录，保存结果后清理该批目录并停止 builder。最新监督器测试的临时目录清理、容器停止均返回 0，测试前后 fixture 目录清单一致。
- 清理只针对已确认归属、未使用且已保留必要证据的编译输出；不运行全局 prune、不删业务卷、不清理脏工作树或用户会话。
- 已完成的私有隔离镜像继续保留供下一阶段使用；镜像构建成功不等于容器运行、systemd 或 cgroup 委派通过。
- 历史清理数字按各自回执计一次，不能在后续报告里重复累计为新释放空间。Docker 稀疏磁盘表观大小、实际分配大小、guest cache 与虚拟机内存分别测量。
